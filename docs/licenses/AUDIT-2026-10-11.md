# Project-wide licence and IP audit — 2026-10-11 (F-PLT-08, with F-CON-03)

Not legal advice; human review is still required before a public release (roadmap §12.4). EU owner.

## 1. Code dependencies [M]

`npx tsx scripts/license-audit.ts --write` → [FULL-TREE.md](FULL-TREE.md): **44 installed packages** on this machine
(22 production, 22 build/test). Licences: MIT 32, OFL-1.1 3 (fonts), BSD-3-Clause 3, Apache-2.0 2, ISC 2, MPL-2.0 2.

* Production stack: reviewed byte-for-byte by Codex (C013/C044, `installed-production.json`); notices generated and
  drift-checked by `npm run licenses:check` (unchanged).
* **New finding:** `npm start` runs the server through **tsx**, a devDependency, which runs **esbuild** (and its Windows
  binary). They are MIT, but they ship with any server deployment and are **not** in `THIRD-PARTY-NOTICES.txt`.
  Proposal (no install needed): either add tsx, esbuild, @esbuild/<platform>, get-tsconfig and resolve-pkg-maps to the
  reviewed notice inventory, or pre-build the server with the already-installed esbuild and run plain `node`.
* **lightningcss** (MPL-2.0, Vite's CSS minifier) is build-only: MPL obligations attach to distributing MPL files, not to
  CSS it outputs; it is never shipped. The audit allows MPL-2.0 only for build-only tools and fails otherwise.
* Packages without a licence file: `@pixi/colord` (resolved by Codex, MIT text retained), the msgpackr/esbuild/rolldown
  platform binaries (each declares MIT and is published from the same project as its parent, whose licence file is
  present). Follow-up for a release: retain the parent licence texts for the binaries that ship (esbuild, msgpackr).
* `npm audit --json` (read-only, 2026-10-11): **0 vulnerabilities** in 99 lockfile entries [M].
* `scripts/license-audit.ts` fails on any licence outside {MIT, ISC, BSD-2/3, Apache-2.0, 0BSD, BlueOak, CC0, Unlicense,
  OFL-1.1, MIT-0, CC-BY-4.0, Python-2.0} (+ MPL-2.0 for build-only tools) and runs in `npm run verify`.
