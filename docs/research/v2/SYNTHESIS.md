# What this evidence changes about the next work

C063, 2026-10-09. Evidence recorded before synthesis in L74. This turns the [priority-game digests](digests/README.md) into bounded decisions and dependencies. Agreement across examples supports an engineering or presentation hypothesis; it does not prove retention, enjoyment or an optimal progression schedule.

| Decision now | Why this follows | Hearthfall consequence / next proof |
|---|---|---|
| Preserve current skill availability and free tier refunds | D3 availability, Idleon talent budgets, TBH investment and TLII rank bonuses are different axes; none supplies a validated pacing target here | C023/C029 remain the measured baseline. Later unlocks or fees need a defined player problem and human evaluation; do not remove existing access to imitate a table |
| Specify objectives as authoritative state transitions before authoring campaign volume | D3/TLII/PoE1/PoE2 separate offer, progress, return and reward choice; reported PoE2 defects distinguish the intended action from incidental state | Extend C040/C041/C051 into a bounded durable-state experiment; define repeat, reconnect, full-bag and restore behavior before live rewards |
| Keep preview, pending operation and committed result explicit | PoE1 labels unconfirmed investment; TBH exposes selected inputs/expected output and reports pending-operation problems; Idleon separates forecast and return | Every future consuming/reward operation needs a commit boundary and recovery behavior. C017 connection receipts are not a durable transaction system; C038 is an isolated candidate, not live integration |
| Keep ownership separate from visibility and collection | Idleon collection/equipped cards, TLII paired bags, PoE1 stash and Hearthfall's full-bag probe distinguish several states | Do not credit an acquisition objective from spawned or visible ground loot. Use actual successful acquisition; separately define current-possession requirements and their consumption |
| Reuse existing panels for explanations | Modifier context and trade-offs recur across games; no source demonstrates that a new visual style is needed | The approved UI remains. Any new message needs local evidence, current-rule text and an actual browser check, including errors |
| Treat offline estimates as estimates | Idleon's estimate/return/acquisition states and event-specific open-client rules cannot establish Hearthfall's offline formula | Keep current measured rules; compare active/offline conditions before changing rates, and test repeat-login/durability independently |
| Carry safety properties through the complete item lifecycle | TBH reports protection lost during equipment, synthesis and restart; TLII backup scope includes separate ownership files | Preserve C053. A later item lock must cover all consumers, movement, save/restore and legacy loading; adding just a padlock is insufficient |
| Target the next missing fact, not another broad footage batch | Seven recordings already cover the priority games/modes, but sparse historical frames cannot answer current errors or ordinary pacing | Finish full-catalogue feature coverage and broader digests. Seek specific current/error evidence only when it can change a pending decision |
