# Quest chapter authoring

Production definitions: `shared/src/data/quests.ts`, `dialogues.ts`, `story.ts`, `questMessages.ts`. Run `npm run content:check` with isolated `DATA_DIR` after every edit. Definitions are trusted repository data, not an uploaded scripting language.

- Keep stable quest/step IDs and pin revisions. Changing an existing objective order needs an explicit save migration. Unknown saved revisions fail closed and retain progress. Never reuse an old ID for a different reward.
- Start/finish contacts are actual people in an authored adventure or human town service NPCs. Every accept, conversation, inspection, delivery and claim rechecks server position/life/line of sight. Opening the journal remotely is allowed; physical actions are not.
- Objectives: `kill` (authored site plus type/family, or its specifically tagged target), `collect` (successful owned ground-item acquisition anywhere in the declared zone; target is a guidance site), `reach`, `talk`, `service`, `rift`, `deliver`, `wave`. `interact` remains the supported object-inspection extension. Only actual server events grant credit. No arbitrary client event endpoint.
- Kill credit defaults to living, same-instance nearby witnesses using the existing XP-share radius; `credit:'killer'` restricts it further. Each hero must already have that objective. Rift credit uses current run membership at Guardian completion, including distant/downed members, as the existing game does. A leave excludes that completion; reconnect/join cannot credit an already finished event. Dungeon waves retain living initiator rules. Other objectives are personal. These are cooperative field/run policies; P10 owns exclusive social parties.
- `minDifficulty` is an existing difficulty index, not a new timed-rift rank. Do not invent a second rank system in quest data.
- Rewards retain `magic_weapon` and `passage`; a bundle can declare `xp`, `gold`, `item:'magic_weapon'`, `unlocks:string[]`. XP is a whole nonnegative value capped at the existing level-cap XP bar; gold is a whole safe value. Values for new live rewards require economy evidence. No new live XP/gold/repeat award was selected in C087.
- Weapon rewards are reserved at final objective completion using the existing class/level/item generator. Claim preflights the entire bundle on a copy. Full bags, overflow or an already-owned reserved ID grant nothing. The new snapshot contains inventory, XP, gold and claimed state together. It is queued through normal character persistence; this is not a claim that every network response was fsynced or that restoring an old backup preserves later history.
- `requires` lists completed quests. `requiresFlags` lists positive flags produced by another quest's `grantsFlags`. Flags and route unlocks derive from valid claimed history, including earlier runs of a repeatable quest. No second mutable flag store.
- `repeat:'on_return'` requires explicit acceptance at the giver after a claim. There is no hidden daily timer. Client `questRequest` sends the exact cycle (next cycle for another acceptance); old accept/claim/delivery/inspection/conversation commands cannot cross cycles. One state, cycle and completion counter per authored quest bounds history; counters cannot exceed safe integers. Existing quests stay one-time; Silent Wheel's legacy adapter cannot repeat.
- Dialogue choices optionally declare positive `when` flag IDs. They only navigate text. Every node must have an unconditional path to an exit; unknown, orphaned and trapped nodes fail validation. Conversation objectives use the explicit server-checked button, not local branch reading.
- Chapters group the existing chain; lore entries identify a quest and completed-step threshold. Recovered text appears only after the authoritative action, and survives claimed/repeated history. Text uses original localized keys.
- Journal filters/search and shared `questMarker` support offered `!`, ready `?`, and active `◆` states. The same rules drive world NPC labels, minimap and area-map pins. The tracked route uses actual connections and physical services. Fog of war and new regions are later content, not prerequisites for the existing network to work.

Validation proves a conservative route/flag/unlock closure, valid references and an actual collision-swept entry path to authored targets on the same diameter grid used by the town validator. It does not prove combat difficulty, RNG drop frequency, player comprehension or future scripts. Existing level gates may require leveling in available fields. A narrow off-grid route may require author adjustment; do not weaken shared collision to pass validation.

Rollback must preserve owned rewards, supported save6 history and active quest definitions. Hide new presentation/capabilities or revert compatible code; do not remove a live unlock definition and silently open its routes. No global quest-off flag was added over already-approved saved adventures: this documented deviation avoids stranding existing characters. Deployment rollout controls can be introduced with account/operations work.
