# Backup size and recovery measurement — C048

L59 precedes this experiment. Claude P3 asks for timed restore evidence; current one-character tests prove scoped correctness, not archive-size cost. Measure installed code before proposing retention or changing allocation. This is standalone research, not a server-load benchmark.

Use two sequential runs each at3,100,1000 synthetic characters. Every child gets a fresh marked temporary DATA_DIR and empty BACKUP_DIR; reject external paths. No game server, personal browser, real save or external download is involved. Generate all three classes cyclically with full60-slot inventory, full60-slot stash and starter equipment using actual item generation, fixed seeds/timestamps and a synthetic unknown extension. Check every item ID is unique inside a character. Report resulting byte counts rather than assume C038's sizes. Counts are coverage/stress fixtures, not predicted population.

Measure actual createCharacterBackup, verifyCharacterBackup and restoreCharacterBackup separately. Wrap only the experiment's snapshot method to time the real capture and submit a later real save through the queue. Prove the backup contains the earlier bytes, the later write reaches the live synthetic directory, and restore preserves the entire older cut including unknown fields. No artificial delay inside snapshot and no game code change. Repeat deterministic fixture/backup/restore hashes; timings are expected to vary.

Use Node24.19.0 [interval-mode event-loop monitoring](https://nodejs.org/download/release/v24.19.0/docs/api/perf_hooks.html#perf_hooksmonitoreventloopdelayoptions) at1ms resolution, record sample count and convert nanoseconds to milliseconds. Warm/reset before each measured operation and allow a final turn afterward. Sample RSS at5ms and immediately before/after; report it as sampled process RSS, not exact per-operation memory, allocation or a peak guarantee. The instrumentation itself costs time. Fresh children isolate prior cases but filesystem caches, antivirus, other PC work and retained buffers affect results. No forced GC, disk-cache eviction, disk/power failure, off-device recovery or tick/FPS certification.

Save compact per-case results and a report; retain generated data only in temporary roots. Do not add timing thresholds to the normal test suite. Standalone strict script typecheck plus byte/conservation assertions validate the harness. Production behavior remains unchanged, so no duplicate game regression run or screenshot is warranted solely for this experiment. If findings justify a change, log a separate evidence-based design before editing runtime code.
