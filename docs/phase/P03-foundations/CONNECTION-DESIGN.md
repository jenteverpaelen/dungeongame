# WebSocket connection boundary — before implementation

2026-10-09. L42/AUTH-06, actual upgrade/IP consumers and primary OWASP/MDN guidance precede this design. This is an independent P3/P16 foundation subset, not account implementation.

Require one exact serialized HTTP(S) Origin in an explicit allowlist before `/ws` upgrade or Session allocation. Reject missing, opaque `null`, malformed, duplicate and unlisted origins with403. Never derive permission from Host or forwarded headers. Default local allowlist: HTTP localhost,127.0.0.1 and[::1], each on configured server PORT and documented Vite5173. A comma-separated `WS_ALLOWED_ORIGINS` override replaces these defaults; validate entries at startup, reject empty/malformed entries/wildcards/paths. Remote/LAN/custom-dev origins must be explicitly configured. Examples and this compatibility change belong in README and operations notes. No public deployment is performed.

Use `req.socket.remoteAddress` for the existing session log. Ignore X-Forwarded-For entirely for now: its only current consumer is attribution, and there is no evidenced trusted proxy topology. Behind a proxy the log intentionally identifies that proxy. Adding trusted traversal later needs deployed topology, address normalization, spoofing tests and purposeful retention. Do not invent a hop count, broad network trust, login throttle or CIDR implementation now.

Existing native test bots must send their known HTTP origin, as browsers do. Do not add a bypass or permit absent Origin. A native attacker can forge it, so character name login remains unauthenticated; account ownership/recovery/HTTPS and independent review remain open. Do not claim the check protects saves from arbitrary native clients.
