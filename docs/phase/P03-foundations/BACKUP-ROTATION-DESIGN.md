# Optional local backup retention

2026-10-09; L65 precedes implementation. Roadmap F-SAV-03/F-OPS-04; no live operator policy is selected.

`BACKUP_KEEP` is an explicit nonnegative safe integer. Missing/empty/zero disables rotation. Invalid values fail startup instead of being silently interpreted. A positive value requires BACKUP_DIR. New version1 manifests include optional `source` SHA256 of a domain-separated host name and canonical DATA_DIR path (lowercase on Windows). This is grouping metadata, not a secret or proof of ownership. Legacy manifests stay verifiable/restorable; rotation excludes them. Moving/restoring the source or changing hostname starts a different group.

After successful capture, the scheduler may call a serialized rotation function with the new directory and configured count. A read-only `plan` CLI uses the same planner. The root and candidates must be regular directories; the anchor must be a direct generated-name child, fully verified, source-scoped and nonempty. Only verified same-source children no later than the anchor and with no IDs missing from it enter the count. Retain the anchor and newest candidates; tie-break equal times by name. All unrecognized/legacy/foreign/invalid/future or missing-character histories are reported as excluded and preserved. The limit is therefore on eligible snapshots, not bytes or total directories.

Before the first removal, verify every survivor again and compare manifests with the plan. Before each candidate removal, verify its data and unchanged manifest. Check resolved direct-child containment, file types and exact entries. Delete individually named regular character files, then their empty directory, then manifest, then empty bundle directory. Never recursive delete. A crash/failure can leave a partial old candidate; subsequent scans preserve it as invalid. Surviving backups must remain intact. No concurrent writer, hostile filesystem race or power-loss guarantee is implied.

Tests: disabled/invalid configuration; three independent snapshots and read-only plan; exact survivor restore; legacy/foreign/extra/incomplete/corrupt/junction/future/missing-character exclusions; root/anchor containment and empty-anchor refusal; failed creation leaves all old bundles; injected deletion failure preserves survivors; scheduler coalescing/shutdown plus separate prune-error log; actual child-server restarts with explicit count and default-off retention. All generated data and fresh DATA_DIR. Full strict suite after integration; no browser change requires a new visual claim.

Removal/effect: only explicitly configured future rotations delete eligible older copies; historical recovery points are lost by that operator choice. Nothing runs against real directories during development. Default retains all; no game data schema/content/UI/camera/town changes. Rollback disables BACKUP_KEEP or removes rotation wiring; it cannot recover already deleted historical copies. Off-device copies, selected calendar policy, multiprocess locking, logical corruption checks and independent operational review remain open.
