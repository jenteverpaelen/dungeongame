# Optional written ground-loot quality — C049

L60 records actual code and primary guidance before design. F-SET-03 requires colour-independent rarity cues. [Game Accessibility Guidelines](https://gameaccessibilityguidelines.com/ensure-no-essential-information-is-conveyed-by-a-fixed-colour-alone/) permits supplementary text as a setting. [XAG103](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/103) separates colour redundancy from nonvisual access; labels alone do not support blind players. Blizzard's [2023 gear-audio discussion](https://news.blizzard.com/en-gb/article/23954932/combatting-demons-with-accessibility-in-diablo-iv) demonstrates additional channels but does not specify this text design.

Add Show loot quality to the existing Sound & comfort panel. Default off preserves the owner's presentation; the explicit note limits it to ground items. When on, prepend a written quality in square brackets to the unchanged item name. Use complete context-specific catalogue messages for Normal/Magic/Rare/Legendary/Set and Ancient/Primal Ancient Legendary/Set, with one name parameter. No ordinal/icon scheme implies Set is universally better than Legendary. Missing rarity stays unspecified rather than guessing Normal. Gems/materials/gold/globes keep existing labels. Preserve font, colours, border/beam/sound, overlap layout, pickup behavior, rarity/drop rates and authoritative item data.

Update already visible labels on the next layout pass when the preference changes; recalculate dimensions and destroy replaced display objects. No per-loot preference subscriptions. Keep ordinary frames allocation-free for this check. Persist the new boolean in the existing version1 preference record; older/malformed values default off and other preferences remain intact. The existing catalogue validator covers all new message keys. No new language or dependency.

Verify legacy/current preference round trips and actual Chrome1920×1080 default/toggle/reload/reset. Retain and inspect screenshots of the existing and enabled labels, a dense cluster, long item names and the setting. Compare default labels/tints/dimensions with the existing renderer and count child objects after repeated toggles. A controlled renderer fixture is not server-earned loot, a player usability test, a colour-vision simulation or a performance benchmark. Keep the approved UI/town/fixed camera. No content is removed; rollback removes the optional renderer/setting/messages together, ignores the extra saved boolean and needs no character migration.
